1. EXECUTIVE SUMMARY & COMPLETED SUCCESSES
================================================================================

1.1. NATIVE FCM PUSH NOTIFICATIONS & AVATAR/APP-LOGO BADGING
- Issue: Users did not see notifications or profile pictures for incoming messages
  and calls when the app was in the background or killed.
- Solution Implemented:
  * Backend push engine configured to emit "data-only" FCM payloads
    (priority: 'high', ttl: 60s, urgency: 'high'). This prevents Android OS from
    displaying generic fallback notifications and hands execution directly to the
    native Android client (`AppFirebaseMessagingService.java` / `AppForegroundService.java`).
  * Circular Profile Avatars + App Logo Badge: Native Android bitmap compositing
    fetches the caller's / sender's profile image over HTTPS, crops it to an anti-aliased
    circle, and overlays the official IChat app badge at the bottom-right corner.
  * Formatted notification text displays:
    [Avatar + App Logo Badge] [Sender / Caller Name] [Message Preview or Call State]

1.2. HEADS-UP BANNER, RINGTONE & VIBRATION FOR CALLING / END CALLING
- Issue: Incoming calls were missed because notifications did not play ringtones,
  vibrate continuously, or display full-screen heads-up banners over other apps.
- Solution Implemented:
  * Android Notification Channel configured with `IMPORTANCE_HIGH` (heads-up banner).
  * System Ringtone integration (`RingtoneManager.TYPE_RINGTONE`) with looping vibration pattern:
    [0, 1000, 1000, 1000, 1000, 1000].
  * Interactive Notification Action Buttons: "Accept" (Green) and "Decline" (Red)
    handling WebRTC call setup or rejection directly from the notification shade.
  * "Call Ended" Event: Incoming call notifications are automatically dismissed
    immediately when caller hangs up, followed by a brief heads-up summary.

1.3. SPEAKERPHONE TOGGLE FIX (LOUDSPEAKER <-> EARPIECE SWITCHING)
- Issue: When a user enabled the loudspeaker on Android, tapping the speaker icon
  could not switch the audio back to the internal phone earpiece.
- Root Cause Identified:
  * In `frontend/src/components/calls/CallModal.tsx`, `<video ref={remoteVideoRef} ...>`
    was unmuted. In Android WebView (Chromium), unmuted HTML5 `<video>` tags bind directly
    to `AudioManager.STREAM_MUSIC`, forcing output through the phone's physical loudspeaker.
    This overpowered native `setSpeakerphoneOn(false)` requests.
- Solution Implemented:
  * Explicitly muted `<video>` (`muted` HTML attribute and `remoteVideoRef.current.muted = true`).
  * Dedicated audio element `<audio ref={remoteAudioRef} />` handles incoming voice exclusively.
  * Native JavaScript bridge calls `window.AndroidAudioBridge.setSpeakerphoneOn(false)`, which
    sets `audioManager.mode = AudioManager.MODE_IN_COMMUNICATION` and `isSpeakerphoneOn = false`,
    safely redirecting audio back to the physical earpiece receiver.
  * Visual feedback: Button toggles between `Volume2` (Speaker) and `Volume1` (Earpiece).

1.4. WEBRTC ACOUSTIC FEEDBACK & SCREECHING INTERFERENCE ELIMINATION (AEC + DTX)
- Issue: Loud screeching, feedback squeals, and comb-filtering occurred when two
  phones answered calls near each other in the same room.
- Solution Implemented:
  * Strict Mono Acoustic Echo Cancellation (AEC) Constraints in `frontend/src/hooks/useWebRTC.ts`:
    channelCount: 1 (Forces mono to prevent multi-mic phase feedback),
    sampleRate: 48000,
    echoCancellation: true,
    noiseSuppression: true,
    autoGainControl: true,
    googEchoCancellation: true,
    googNoiseSuppression: true,
    googHighpassFilter: true,
    googTypingNoiseDetection: true.
  * SDP Opus Audio Optimization (`optimizeSdpForVoice`):
    Before WebRTC peer exchange, session description protocols (SDP) are dynamically rewritten
    to append Opus parameters:
    `stereo=0;sprop-stereo=0;useinbandfec=1;usedtx=1;maxaveragebitrate=32000`
  * Enabling `usedtx=1` (Discontinuous Transmission) instructs the codec to stop transmitting
    audio packets entirely when the user is silent, instantly cutting acoustic feedback loops.

1.5. REAL-TIME ADMIN REGISTRATION PUSH NOTIFICATION ALERTS
- Requirement: Admins must be instantly alerted when a new user registers on the platform.
- Solution Implemented:
  * Added automated push dispatch in `backend/src/sockets/socketHandler.ts` inside
    `broadcastNewUserRegistered`.
  * Target: Users with `role === 'admin'`, phone number `02054245616`, and master admin ID
    `usr-0bb5adab-47d6-43d7-8d4e-37288c70fc01`.
  * Sends an immediate high-priority FCM and Web Push alert:
    "New Registration: [Name] has just joined IChat (+[Phone])".

1.6. OFFLINE-FIRST PWA, INSTANT CACHING & AIRPLANE MODE DATA PERSISTENCE
- Issue: Turning on Airplane Mode or opening the app without internet caused a blank
  white screen and wiped out chat/contact lists.
- Solution Implemented:
  * Nginx Caching Policy: Stripped `no-store` headers; configured `/assets/` with
    `Cache-Control: public, max-age=31536000, immutable`, and `/` with `no-cache` for instant
    Service Worker lifecycle updates.
  * Service Worker Runtime Precaching (`frontend/public/sw.js` and `frontend/src/main.tsx`):
    Automatically discovers and precaches HTML, JS/CSS bundles, manifest, and icons on app boot.
    Implements Cache-First and Stale-While-Revalidate strategies for sub-second offline boot.
  * Inline Dark Shell (`frontend/index.html`): Added inline dark styling (`#111b21`) and IChat
    SVG splash screen directly to root HTML. Zero blank white screen during cold starts offline.
  * Local Storage Persistence:
    Chats and contacts are backed up to `ichat_chats_backup` and `ichat_contacts_backup`.
    State initializes synchronously from localStorage on startup before any network call.
  * In-App Connectivity Banner: Real-time banner displays "No internet connection. Showing cached messages."
    when offline, automatically disappearing once connectivity is restored.

5. DATA MIGRATION, PERSISTENCE & RESTORE PROCEDURE
================================================================================

5.1. FILES & DATABASES REQUIRING BACKUP
1. Primary App Store (`store.json`): Contains all users, messages, contacts,
   push tokens, channel subscriptions, and call logs.
   Location inside container: `/app/data/store.json`
   Named Docker Volume: `backend_data`
2. PostgreSQL Database: `whatsapp_business`
   Named Docker Volume: `postgres_data`
3. Uploads Directory: `/var/www/chat-app/backend/uploads` (profile photos, voice notes, media)

5.2. BACKUP COMMAND ON OLD SERVER (150.95.30.215)
Run on the old server:
mkdir -p /root/migration_backup

# 1. Backup store.json
docker cp whatsapp_backend:/app/data/store.json /root/migration_backup/store.json

# 2. Dump PostgreSQL database
docker exec -t whatsapp_postgres pg_dump -U postgres whatsapp_business > /root/migration_backup/whatsapp_business.sql

# 3. Archive uploaded media
tar -czf /root/migration_backup/uploads.tar.gz -C /var/www/chat-app/backend uploads/

# Transfer backup archive to new server:
scp -r /root/migration_backup root@[NEW_SERVER_IP]:/root/

5.3. RESTORE COMMAND ON NEW SERVER
Run on the new server after launching Docker containers:

# 1. Restore store.json
docker cp /root/migration_backup/store.json whatsapp_backend:/app/data/store.json
docker exec whatsapp_backend chown -R node:node /app/data/store.json

# 2. Restore PostgreSQL database
docker exec -i whatsapp_postgres psql -U postgres whatsapp_business < /root/migration_backup/whatsapp_business.sql

# 3. Restore uploaded media
tar -xzf /root/migration_backup/uploads.tar.gz -C /var/www/chat-app/backend/

# 4. Restart backend container to reload restored state
docker restart whatsapp_backend

7. ANDROID MOBILE APP (CAPACITOR) ARCHITECTURE
================================================================================

7.1. ZERO-APK-REBUILD GUARANTEE FOR EXISTING USERS
- The installed Android APK is a Capacitor-wrapped progressive hybrid application.
- All UI components, WebRTC audio fixes, Service Worker caching, and React logic
  are served dynamically from `https://chat.on-excapp.app`.
- As long as the domain `chat.on-excapp.app` points to the new server with valid SSL,
  all existing installed devices (Vivo, Infinix, Samsung, etc.) will automatically
  receive all updates on app restart WITHOUT needing to reinstall the APK.

7.2. NATIVE ANDROID BRIDGE & PUSH RECEIVER NOTES
The Android native layer includes two crucial bridges:
1. `AndroidAudioBridge`:
   - Method: `setSpeakerphoneOn(boolean on)`
   - Manages `AudioManager.MODE_IN_COMMUNICATION` and `isSpeakerphoneOn`.
   - Allows switching between loudspeaker and physical earpiece receiver.
2. `AppFirebaseMessagingService`:
   - Listens to high-priority FCM data payloads.
   - Decodes caller avatars and overlays the circular IChat logo badge.
   - Fires heads-up banners with full-screen intent, ringtone, and vibration.

7.3. CAPACITOR CONFIGURATION (Reference: android/capacitor.config.ts)

  appId: 'com.onexcapp.ichat',

  webDir: 'dist',
  server: {
    url: 'https://chat.on-excapp.app',
    cleartext: false
  }
}

Certbot installs an automatic systemd renewal timer. Verify with:
sudo systemctl status certbot.timer
sudo certbot renew --dry-run
